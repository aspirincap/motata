# Motata 0.2.0 发布说明与升级注意

日期：2026-09-08
状态：0.2.0 候选已准备，尚未发布至 npm/PyPI，未部署 Cloudflare registry。工作分支为 `codex/hardening-release-0.2.0`，尚未合并 main 或创建发布标签。

本版集中修复失败被当作成功、跨币种金额混算、迁移中断后重复写入和 npm runtime 半安装等问题，并收齐共享层、业务服务、报告渲染器、registry 源码及发布门禁。升级前请检查调用脚本对退出码、默认状态和输出字段的处理。

## 兼容性变化

| 变化 | 升级后的处理方式 |
|---|---|
| 退出码统一为 `0` 成功或明确计划、`1` 失败/待核验、`2` 参数错误、`3` 部分成功/降级 | 收到 `3` 时保留产物并检查 `completeness`，不要按完整成功继续执行 |
| TikTok copy/bootstrap 的 Campaign、Adgroup、Ad 默认全部 `DISABLE` | 激活需显式指定；这些命令仍会真实创建对象 |
| Meta `validate creative/ad-link/promoted-object` 要求 `--allow-live-probe` | 探针会真实创建对象，`--cleanup` 仅尽力清理；`PAUSED` 不代表 dry-run |
| 混合币种的全局金额和 ROAS 可为 `null` | 不要转成零；排名及 top-N 按币种计算，未知币种按账户隔离 |
| npm CLI 相对路径按调用目录解析 | 检查原先依赖 npm 包目录的路径；必要时传绝对路径 |
| Meta migration 恢复要求 schema v1 checkpoint | 旧 job 不会自动重跑；按名称复用不再生效 |
| 新增 `motata report render-gmv-max` | `report ... run` 生成的 manifest 仍是采集结果；HTML 需要单独渲染，默认离线，下载图片需 `--cache-images` |

## 主要修复

- 统一诊断脱敏，覆盖分页 URL、嵌套/转义 JSON、完整 Cookie 头和异常；Auth Center 按指定账户跨页查找，失败时不再输出全账户 token 响应。
- 请求采用有限超时；只读重试有次数上限，指标降级仅用于明确的不兼容错误。分页截断、来源失败和警告传递到报告完整性结果。
- Meta migration 在写入前保存 `pending`，取得明确目标 ID 后保存 `confirmed`；超时、中断或无法持久化确认时进入 `needs_review`。视频写入不盲重试，分片 offset 必须连续且有效，finish 必须明确成功；缺失或错配的 creative 引用在首个写入前拒绝。
- npm runtime 增加初始化锁、版本/健康检查和半安装恢复；Windows npm/npx 使用 Node 入口，保留参数原值。wheel、sdist、npm 包含必要源码、兼容性资源和第三方声明。
- 五个 skills 的发布源码统一放在 `registry/skills/`，构建验证文件范围并记录 SHA-256。普通命令的提示只读本地状态；registry snapshot 一致不表示本机已安装内容已逐字节验证。

## 安装与恢复注意

Python 要求为 **3.11 或更新版本**；npm 包要求 Node.js **18 或更新版本**。版本发布后按现有 npm/PyPI 渠道升级，并用 `motata --version` 核对。npm 会按版本及健康检查结果重建包内 `.runtime/venv`，首次引导仍需要可用的 Python 和依赖来源。

升级前保留 migration 的 checkpoint、export 和请求回执。恢复时使用原 job ID 与原配置/export；更换或修补 export 会触发指纹保护。已确认写入会被跳过；`needs_review` 必须先核对远端 ID、目标账户归属和请求内容，不能凭同名对象认领，也不能换新 job 绕过保护。`cleanup_plan` 仅列计划，不执行删除。

TikTok copy/bootstrap 会保留部分成功对象清单，但尚不具备 Meta migration 的恢复 ledger。报告完整性反映覆盖与错误情况，不保证上游归因口径或业务结论正确；Product intake 输出事实和策略提示，不自动完成预算、实验方案或投放执行。
